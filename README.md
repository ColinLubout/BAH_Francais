# BAH Français

A mobile app for learning and maintaining French through short, self-paced drills
with spaced repetition (FSRS). Offline, no accounts, no tracking, no streaks.
Everything after the welcome screen is in French.

Flutter, for iOS 15+ and Android 8.0+ (API 26). MIT licence.

**Status:** milestone 1 of 8 (the domain core: scheduling, grading, the card queue).
See [PROGRESS.md](PROGRESS.md) for where things stand, and
[docs/SPEC.md](docs/SPEC.md) for the full specification.

## Setup

You need Flutter **3.47.2** (stable), the version CI uses. For Android builds,
install Android Studio or a JDK 17+ with the Android SDK. For iOS builds you need
macOS with Xcode.

```bash
flutter pub get
dart run build_runner build   # Riverpod and Drift code generation
flutter run
```

The code generated by `build_runner` (`*.g.dart` and `*.drift.dart`) is not
committed, so run it after every fresh clone and whenever you change a provider, a
table or a database class.

## Commands

```bash
dart run build_runner build                   # Riverpod + Drift codegen
dart run tool/gen_strings.dart                # strings/*.json -> lib/core/strings.g.dart
flutter analyze
dart format --set-exit-if-changed .
flutter test --coverage
dart run tool/check_domain_coverage.dart     # domain layer coverage must be at least 90%
dart run tool/content_build.dart content/sample  # validate content and build its pack
dart run drift_dev make-migrations            # after a schema change: dump it, add migration tests
dart run flutter_launcher_icons               # regenerate app icons
dart run flutter_native_splash:create         # regenerate launch screens
```

CI (`.github/workflows/ci.yml`) runs on every pull request and every push to `main`.
It checks that `strings.g.dart` is up to date, validates the sample content and builds
its pack, and runs the format check, the analyzer and the tests with coverage
(uploaded to Codecov), then fails if the domain layer is under 90% coverage. It also
makes a debug Android build and an unsigned iOS build.

## Architecture

```
lib/
  main.dart            start-up
  app/                 the app widget, routing (go_router), the navigation bar shell
  core/
    strings.g.dart     generated from strings/ (never edit by hand)
    theme/             colours, Poppins text styles, feedback colours
    database/          the Drift database
  features/
    <feature>/
      data/            Drift tables, DAOs, queries
      domain/          pure Dart: scheduling, grading, queue building (no Flutter imports)
      presentation/    widgets and Riverpod providers (no business logic)
tool/                  command-line tools: strings generator, content validator and pack builder
content/
  schema/              the JSON Schema of each kind of content file
  sample/              a small sample set for development and tests; never shipped
drift_schemas/         every version of the database schema, for migration tests
strings/               every piece of user-facing text
assets/                fonts and branding images
test/                  mirrors lib/ and tool/; test/drift/ holds the migration tests
```

- **Features first:** each feature has its own folder. Inside it, `data/`, `domain/`
  and `presentation/` keep storage, logic and UI apart. The domain layer is pure Dart,
  so it can be tested without a widget tree.
- **Riverpod** handles state and dependency injection, with code-generated providers.
  There is no service locator.
- **Drift** stores everything in SQLite, on the device. Every schema change raises
  the schema version, ships with a migration, and is dumped with
  `dart run drift_dev make-migrations`, with a test that opens the previous version.
- **Content** (words, verbs, sentences, images) is written as JSON files, one noun
  category or one verb per file. `tool/content_build.dart` checks them against
  `content/schema/` and the rules beyond it, then builds a content pack: one SQLite
  file with the app's content tables, which the app imports on first launch.
- **go_router** handles routing. The five screens in the bottom navigation bar are
  branches of one shell route.

## Text and translations

Every word the app shows comes from two JSON files:

- `strings/strings_fr.json`: the whole app, in French.
- `strings/strings_en_welcome.json`: the welcome screen, the only screen in English.

`tool/gen_strings.dart` turns them into typed Dart classes (`Strings` and
`WelcomeStrings` in `lib/core/strings.g.dart`), which widgets use instead of literal
text. It works like this:

- A key becomes one member, named from its path: `home.dueCount` becomes
  `Strings.homeDueCount`.
- Text with placeholders becomes a method with named parameters:
  `Strings.homeDueCount(n: 12)`.
- Allowed placeholders are `{n}`, `{version}`, `{date}`, `{size}`, `{drill}`, `{answer}`
  and `{word}`. `n` and `version` are numbers; the others are text the caller formats.
- For a plural, write two keys, `key_one` and `key_other`. French uses `_one` for 0
  and 1.
- Keys starting with `_` are notes and are skipped.

The generator stops with a list of problems for an unknown placeholder, a broken
brace, empty text, a badly named key or a duplicate name. New text means a new key
first, then run the generator.
